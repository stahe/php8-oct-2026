    9. Les traits

    Les traits sont des structures analogues à des classes. On ne peut cependant pas les instancier : ils sont destinés à être inclus dans des classes. L'inclusion d'un trait dans une classe a le même effet que si l'on avait copié le code du trait dans la classe. On met dans un trait du code susceptible d'être réutilisé dans plusieurs classes.

    Les traits existent depuis PHP 5.4. PHP 8 leur a apporté quelques compléments que nous présenterons à la fin du chapitre : vérification de la signature des méthodes abstraites (PHP 8.0), constantes de trait (PHP 8.2), attribut [#[\Override]] utilisable dans un trait (PHP 8.3).

    <?php

declare(strict_types=1);

class Class04
{
    // constructeur avec promotion de l'attribut [name]
    public function __construct(private string $name)
    {
    }

    // getter et setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

trait Trait04
{
    // attribut
    private string $name;

    // getter et setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

class Class05
{
    // inclusion du trait
    use Trait04;

    // constructeur
    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

// test --------------
$class04 = new Class04("Tim");
$class05 = new Class05("Burton");
print $class04->getName() . "\n";
print $class05->getName() . "\n";
// affichage des deux objets
print_r($class04);
print_r($class05);

    Commentaires du code

    • lignes 5-22 : définition de la classe [Class04] avec un attribut [$name] (promu par le constructeur), son getter, son setter ;
    • lignes 24-39 : on reprend le code de [Class04] sans son constructeur et on le transfère dans le trait [Trait04]. L'attribut est cette fois déclaré explicitement, avec son type. On ne reprend pas le constructeur puisqu'un trait n'est pas instanciable ;
    • ligne 24 : c'est le mot clé [trait] qui fait de [Trait04] un trait plutôt qu'une classe ;
    • lignes 41-51 : on définit une classe [Class05] qui inclut le code du trait [Trait04] et lui ajoute un constructeur, pour rendre la classe instanciable ;
    • ligne 44 : c'est le mot clé [use], placé à l'intérieur de la classe, qui permet l'inclusion d'un trait dans une classe. Il ne faut pas le confondre avec l'instruction [use] placée en dehors de toute classe, qui importe un nom d'un espace de noms ;
    • lignes 54-60 : des tests montrent que les classes [Class04] et [Class05] fonctionnent de la même façon .

    <?php

declare(strict_types=1);

trait Trait01
{
    // attribut
    private int $id = 0;

    // méthode
    public function doSomething(): void
    {
        print "Trait01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // inclusion de Trait01
    use Trait01 {
        // la méthode [Trait01::doSomething] est accessible
        // dans la classe sous le nom [doSomethingInTrait]
        Trait01::doSomething as doSomethingInTrait;
    }

    // méthode propre à la classe
    public function doSomething(): void
    {
        // attribut id
        $this->id += 10;
        // utilisation de la méthode de Trait01
        $this->doSomethingInTrait();
        // affichage local
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // inclusion de Trait01
    use Trait01;

    // méthode locale à la classe
    public function doSomethingElse(): void
    {
        // attribut id
        $this->id += 10;
        // utilisation de la méthode de Trait01
        $this->doSomething();
        // affichage local
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    $class02 = new Class02();
    $class03 = new Class03();
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();

    Commentaires

    • lignes 5-15 : un trait définissant un attribut [$id] et une méthode [doSomething] ;
    • le trait [Trait01] est inclus dans deux classes [Class02] (lignes 17-36) et [Class03] (lignes 38-53) ;
    • lignes 20-24 : inclusion de [Trait01] dans [Class02]. L'inclusion est suivie d'un bloc [{...}] qui permet d'ajuster les méthodes incluses ;
    • ligne 23 : cette ligne résout un conflit : [Trait01] et [Class02] ont tous les deux une méthode appelée [doSomething]. Dans ce cas, c'est la méthode de la classe qui l'emporte : la méthode du trait est masquée. L'opérateur [as] rend la méthode [Trait01::doSomething] accessible dans la classe sous le nom [doSomethingInTrait]. Ainsi, à l'intérieur de [Class02], on utilisera les notations :
      • [doSomethingInTrait] pour appeler la méthode [Trait01::doSomething] ;
      • [doSomething] pour appeler la méthode [Class02::doSomething] ;
    • lignes 30-32 : la classe [Class02] utilise l'attribut et la méthode de [Trait01] comme s'ils lui étaient propres ;
    • lignes 38-53 : la classe [Class03] est analogue à la classe [Class02]. L'inclusion de [Trait01] est ici plus simple parce qu'il n'y a pas de collision entre les méthodes de [Trait01] et de [Class03] .

    <?php

declare(strict_types=1);

// classe qui remplace le trait
class Class01
{
    // attribut
    private int $id = 0;

    // setter
    public function setId(int $id): void
    {
        $this->id = $id;
    }

    // getter
    public function getId(): int
    {
        return $this->id;
    }

    // méthode
    public function doSomething(): void
    {
        print "Class01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // une référence sur une instance de Class01, injectée par le constructeur
    public function __construct(private readonly Class01 $class01)
    {
    }

    // méthode propre à la classe
    public function doSomething(): void
    {
        // modification de l'attribut de Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // utilisation de la méthode de Class01
        $this->class01->doSomething();
        // affichage local
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // une référence sur une instance de Class01, injectée par le constructeur
    public function __construct(private readonly Class01 $class01)
    {
    }

    // méthode locale à la classe
    public function doSomethingElse(): void
    {
        // modification de l'attribut de Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // utilisation de la méthode de Class01
        $this->class01->doSomething();
        // affichage local
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    // deux objets qui vont accéder à deux instances différentes de [Class01]
    $class02 = new Class02(new Class01());
    $class03 = new Class03(new Class01());
    // vérification
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test02 ----------------
function test02(): void
{
    // instance partagée de [Class01]
    $class01 = new Class01();
    // deux objets qui vont accéder à la même instance de [Class01]
    $class02 = new Class02($class01);
    $class03 = new Class03($class01);
    // vérification
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();
// test02
print "test02-----------------\n";
test02();

    Commentaires

    • lignes 6-28 : la classe [Class01] remplace le trait [Trait01]. Le code de [Trait01] était incorporé au code des classes [Class02] et [Class03]. Ici, ce ne sera pas le cas : c'est une référence à un objet [Class01] qui sera injectée dans les classes [Class02] et [Class03]. Les attributs de la classe [Class01] seront donc extérieurs aux objets [Class02] et [Class03]. Comme l'attribut [$id] est privé, il faut prévoir un getter et un setter. C'est la 1re différence avec le trait : il faut créer le code d'accès aux attributs privés de la classe. On aurait pu rendre l'attribut [$id] public mais ce n'est pas conseillé : passer par un setter pour fixer la valeur d'un attribut permet d'en vérifier la validité ;
    • ligne 33 : la référence à l'objet [Class01] est injectée dans [Class02] par son constructeur, grâce à la promotion des paramètres. Le cours PHP 7 utilisait un setter [setClass01]. L'injection par le constructeur est préférable : l'objet [Class02] est complet dès sa construction et, l'attribut étant [readonly], la référence ne peut plus être changée ;
    • lignes 41-45 : pour tout usage du code de [Class01], il nous faut passer par l'attribut [$this->class01] ;
    • lignes 51-70 : la classe [Class03] est un clone de la classe [Class02] si ce n'est que sa méthode a un nom différent ;
    • lignes 73-81 : le 1er test. Celui-ci consiste à injecter dans les objets [Class02] et [Class03] deux instances différentes de la classe [Class01] ;
    • lignes 84-94 : le 2e test injecte dans les objets [Class02] et [Class03] la même instance de la classe [Class01] .

On en conclura que si des attributs doivent être partagés entre des objets, le trait n'est pas utilisable et il faut alors utiliser une classe .

    9.4. Regrouper des méthodes dans un trait

    Dans l'exemple précédent, le trait comportait des attributs et des méthodes. Nous considérons ici le cas où il ne contient que des méthodes. Le trait ressemble alors à une factorisation de méthodes qu'on peut utiliser dans différentes classes. Comme le trait n'a ici pas d'attribut, on va considérer le cas où les méthodes qu'il rassemble travaillent uniquement sur des paramètres qu'on leur passe. Ce n'est pas obligatoire : un trait peut travailler sur un attribut [$this->attribut1] sans avoir cet attribut. C'est alors aux classes qui utilisent ce trait de fournir l'attribut [$this->attribut1].

    Dans le cas où le trait n'a que des méthodes qui travaillent uniquement sur des paramètres qu'on leur passe, nous montrerons que le trait peut être remplacé par une classe ayant les mêmes méthodes que le trait, déclarées statiques.

    L'utilisation du trait est illustrée par le script [trait-04.php] qui reprend le trait de l'exemple précédent en lui enlevant tout attribut :

trait Trait01
{

Nous verrons à la fin du chapitre que PHP 8 offre une solution propre pour exiger quelque chose des classes qui utilisent un trait : les méthodes abstraites.

    9.5. Héritage multiple avec un trait

declare(strict_types=1);

trait Trait01
{
    // attribut
    private int $i = 0;

    // méthode à partager
    public function doSomethingInTrait01(): void
    {
        // modification de Trait01::$i
        $this->i++;
        // affichage
        print "Trait01::doSomethingInTrait01... i=$this->i\n";
    }
}

class Class02
{
    // attribut accessible aux classes dérivées
    protected int $j = 0;

    // méthode
    public function doSomethingInClass02(): void
    {
        // modification de Class02::$j
        $this->j += 10;
        // affichage
        print "Class02->doSomethingInClass02... j=$this->j\n";
    }
}

// classe dérivée
class Class03 extends Class02
{
    // hérite de Class02::$j et inclut Trait01::$i
    use Trait01;

    // méthode
    public function doSomethingInClass03(): void
    {
        // utilisation de la méthode de Trait01
        $this->doSomethingInTrait01();

    9.6. Utiliser un trait à la place d'une classe abstraite

    On rencontre souvent le cas d'utilisation suivant : on crée une interface I assez générale qui peut donner naissance à plusieurs implémentations. Celles-ci partagent un code commun mais diffèrent par d'autres méthodes. On peut implémenter ce cas d'utilisation de deux façons :

    • on crée une classe abstraite C qui regroupe le code commun aux classes dérivées. La classe C implémente l'interface I mais certaines méthodes, qui doivent être définies dans les classes dérivées, sont déclarées abstraites dans la classe C, qui est donc elle-même abstraite. On crée ensuite des classes C1 et C2 dérivées de C qui implémentent chacune à leur manière les méthodes abstraites de leur classe parent C ;
    • on crée un trait T quasi identique à la classe abstraite C de la solution précédente. Ce trait n'implémente pas l'interface I car syntaxiquement il ne le peut pas. On crée ensuite des classes C1 et C2 implémentant l'interface I et utilisant le trait T. Il ne reste plus à ces classes qu'à implémenter les méthodes de l'interface I non implémentées par le trait T qu'elles importent .

    Voici un exemple qui montre la grande proximité de ces deux solutions. L'application 1 implémente la solution 1 [trait-08.php] :

    <?php

declare(strict_types=1);

interface Interface1
{
    public function doSomething(): void;

    public function doSomethingElse(): void;
}

abstract class AbstractClass implements Interface1
{
    // attributs accessibles aux classes dérivées
    protected int $attr1 = 11;
    protected int $attr2 = 12;

    // getters et setters
    public function getAttr1(): int
    {
        return $this->attr1;
    }

    public function getAttr2(): int
    {
        return $this->attr2;
    }

    public function setAttr1(int $attr1): static
    {
        $this->attr1 = $attr1;
        return $this;
    }

    public function setAttr2(int $attr2): static
    {
        $this->attr2 = $attr2;
        return $this;
    }

    // méthode implémentée
    #[\Override]
    public function doSomething(): void
    {
        print "AbstractClass::doSomething [$this->attr1,$this->attr2]\n";
    }

    // méthode non implémentée
    #[\Override]
    abstract public function doSomethingElse(): void;
}

// classe dérivée 1
class Class1 extends AbstractClass
{
    // attribut
    private int $attr3 = 13;

    // getter et setter
    public function getAttr3(): int
    {
        return $this->attr3;
    }

    public function setAttr3(int $attr3): static
    {
        $this->attr3 = $attr3;
        return $this;
    }

    // implémentation de doSomethingElse
    #[\Override]
    public function doSomethingElse(): void
    {
        print "Class1::doSomethingElse [$this->attr1,$this->attr2,$this->attr3]\n";
    }
}

// classe dérivée 2
class Class2 extends AbstractClass
{
    // attribut
    private int $attr4 = 14;

    // getter et setter
    public function getAttr4(): int
    {
        return $this->attr4;
    }

    public function setAttr4(int $attr4): static
    {
        $this->attr4 = $attr4;
        return $this;
    }

    // implémentation de doSomethingElse
    #[\Override]
    public function doSomethingElse(): void
    {
        print "Class2::doSomethingElse [$this->attr1,$this->attr2,$this->attr4]\n";
    }
}

// fonction externe
function useInterfaceWith(Interface1 $interface): void
{
    $interface->doSomething();
    $interface->doSomethingElse();
}

// tests
useInterfaceWith(new Class1());
useInterfaceWith(new Class2());
// les setters « fluents » peuvent être enchaînés
useInterfaceWith((new Class1())->setAttr1(21)->setAttr2(22)->setAttr3(23));

    Commentaires

    • lignes 5-10 : l'interface [Interface1] a deux méthodes ;
    • ligne 12 : la classe abstraite [AbstractClass] implémente l'interface [Interface1]. Elle a deux attributs avec leurs getters et setters, implémente la méthode [doSomething] de l'interface [Interface1] (ligne 43) mais ne sait pas implémenter la méthode [doSomethingElse]. Celle-ci est donc déclarée abstraite (ligne 50). La classe abstraite [AbstractClass] ne peut être instanciée et pour servir à quelque chose elle doit obligatoirement être dérivée ;
    • lignes 29-39 : les setters sont « fluents » : au lieu de ne rien rendre, ils rendent l'objet [$this]. Cela permet d'enchaîner les appels (ligne 116). Le type de retour [static] (PHP 8.0) désigne la classe de l'objet sur lequel la méthode a été appelée : [(new Class1())->setAttr1(21)] est de type [Class1] et non [AbstractClass], ce qui permet d'appeler ensuite [setAttr3], méthode propre à [Class1] ;
    • ligne 54 : la classe [Class1] étend la classe abstraite [AbstractClass] et donc implémente l'interface [Interface1]. Elle donne un corps à la méthode [doSomethingElse] que sa classe parent n'avait pas définie. Elle ajoute également un attribut à ceux de sa classe parent ;
    • ligne 80 : la classe [Class2] fait de même avec un autre attribut ;
    • lignes 106-110 : la fonction [useInterfaceWith] reçoit en paramètre un type [Interface1] et appelle les deux méthodes de cette interface ;
    • lignes 113-116 : on appelle la fonction [useInterfaceWith] avec un type [Class1] puis avec un type [Class2]. C'est correct puisque ces deux types implémentent l'interface [Interface1] .

    <?php

declare(strict_types=1);

// un trait qui exige quelque chose des classes qui l'utilisent
trait TraitCompteur
{
    // constante de trait (PHP 8.2)
    public const int PAS = 10;

    // attribut statique : chaque classe utilisatrice a le sien
    private static int $nbInstances = 0;

    // attribut d'instance
    private int $compteur = 0;

    // méthode statique de trait
    public static function getNbInstances(): int
    {
        return self::$nbInstances;
    }

    // méthode abstraite : la classe utilisatrice doit la définir (signature vérifiée depuis PHP 8.0)
    abstract protected function getNom(): string;

    // à appeler par le constructeur de la classe utilisatrice
    private function enregistrer(): void
    {
        self::$nbInstances++;
    }

    // méthode concrète qui utilise la méthode abstraite et la constante
    public function incrémenter(): static
    {
        $this->compteur += self::PAS;
        print "{$this->getNom()} : compteur=$this->compteur\n";
        return $this;
    }
}

class Voiture
{
    use TraitCompteur;

    public function __construct(private string $immatriculation)
    {
        $this->enregistrer();
    }

    // implémentation de la méthode abstraite du trait
    #[\Override]
    protected function getNom(): string
    {
        return "Voiture[$this->immatriculation]";
    }
}

class Velo
{
    use TraitCompteur;

    public function __construct()
    {
        $this->enregistrer();
    }

    #[\Override]
    protected function getNom(): string
    {
        return "Vélo";
    }
}

// tests
(new Voiture("AB-123-CD"))->incrémenter()->incrémenter();
new Voiture("EF-456-GH");
(new Velo())->incrémenter();
// chaque classe a son propre attribut statique
print "nombre de voitures : " . Voiture::getNbInstances() . "\n";
print "nombre de vélos : " . Velo::getNbInstances() . "\n";
// la constante du trait est accessible via la classe, pas via le trait
print "pas : " . Voiture::PAS . "\n";
try {
    print TraitCompteur::PAS . "\n";
} catch (\Error $ex) {
    print $ex::class . " : " . $ex->getMessage() . "\n";
}
// une classe qui utilise le trait doit implémenter la méthode abstraite
// class Avion { use TraitCompteur; }  // Fatal error : Class Avion contains 1 abstract method...

    Commentaires

    • ligne 9 : depuis PHP 8.2, un trait peut déclarer des constantes. Elles deviennent des constantes de la classe qui utilise le trait ;
    • ligne 12 : un trait peut déclarer des attributs statiques. Comme les attributs d'instance, ils sont recopiés dans chaque classe qui utilise le trait : chaque classe a son propre compteur d'instances ;
    • lignes 18-21 : un trait peut déclarer des méthodes statiques. Dans le code du trait, [self] désigne la classe qui utilise le trait ;
    • ligne 24 : un trait peut déclarer des méthodes abstraites. Toute classe qui utilise le trait doit les implémenter, sinon elle doit elle-même être déclarée abstraite (voir la classe [Avion] en commentaire à la fin du script). Depuis PHP 8.0, la signature de l'implémentation (types des paramètres et du résultat) est vérifiée. C'est la façon propre d'exiger quelque chose des classes qui utilisent le trait, plutôt que de supposer qu'elles ont tel attribut ou telle méthode ;
    • lignes 33-38 : une méthode concrète du trait qui utilise la méthode abstraite [getNom] et la constante [PAS]. Elle rend [$this] (type [static]) pour pouvoir être enchaînée ;
    • lignes 41-56 : la classe [Voiture] utilise le trait, appelle la méthode privée [enregistrer] du trait dans son constructeur et implémente la méthode abstraite [getNom]. On remarquera l'attribut [#[\Override]] sur cette implémentation : il est accepté parce que la méthode implémente une méthode abstraite du trait ;
    • lignes 58-72 : la classe [Velo] fait de même ;
    • lignes 79-80 : chaque classe a son propre attribut statique [$nbInstances] ;
    • ligne 82 : la constante du trait est accessible via la classe qui l'utilise ;
    • ligne 84 : mais pas directement via le trait : on obtient une erreur .

    9.8. Conclusion

    Des exemples précédents, il ressort que les cas d'utilisation où l'usage du trait amène un avantage net ne sont pas évidents. Sur nos exemples, on peut toujours s'en passer en le remplaçant par une classe. Son utilisation est cependant pratique pour factoriser du code entre différentes classes, comme si ce code appartenait à une classe parent, sans consommer l'unique héritage dont dispose une classe PHP. C'est ce que nous ferons dans la version 4 de l'exercice d'application.
